## What you are building

`checkpoint-a/solution.js`, exporting five functions. They read from
`orders-db.js`, which behaves exactly like module 08's fake database: it
answers after a short delay, and asking for an id that does not exist
**rejects**.

An order looks like this:

```js
{ id: 7, student: "Laila Hosny", city: "Aswan", item: "Stapler",
  quantity: 3, price: 70, status: "paid" }
```

`price` is the price of **one** item, in EGP.

---

## 1. `loadOrders()`

`async`. Returns every order from the database, as an array.

## 2. `myOrders(orders)`

Takes an array of orders. Returns only the ones that are **both**:

- from **Alexandria**, and
- with status **paid**

Not async — it is given the list.

## 3. `summarize(orders)`

Takes an array of orders. Returns **number of items**, as a number.

> Add up `quantity` for every order in the list.

Not async.

## 4. `describeOrder(id)`

`async`. Looks up one order by its id and returns a label in exactly this
shape:

```
{item} x{quantity} ordered by {student}
```

For the made-up order above, that would be:

```
Stapler x3 ordered by Laila Hosny
```

If there is **no order with that id**, the lookup rejects. Catch it and return
exactly:

```
Could not find order {id}
```

so that `describeOrder(9999)` returns `"Could not find order 9999"`.
This function must never throw.

## 5. `toJsonLines(orders)`

Takes an array of orders. Returns **JSON text** for an array of objects
keeping only `item` and `price` from each order, in that order, and nothing else.

For a list holding only the made-up order above:

```
[{"item":"Stapler","price":70}]
```

Plain `JSON.stringify` output — no indenting.
